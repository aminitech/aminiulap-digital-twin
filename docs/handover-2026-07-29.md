## 2. `examples/` — the new front door

23 tracked files. Runs on **numpy + matplotlib only** — no Blender, no GDAL, no
Sionna. The point is that someone can `git clone` and be looking at coverage maps
in about a minute, which the real pipeline (three Python environments) can't offer.

```
examples/
  ulap_demo/          scene loading, the analytical radio model, plotting
  data/               open sample scene + fetch_open_scene.py + placeholders
  notebooks/          01–04, in order
  apps/               3 runnable local apps
  tests/              75 tests, pins the claims the notebooks make
```

**4 notebooks:** define a study → link budget vs. real ray-traced data → scene &
terrain geometry → coverage/SINR maps.

**3 apps:** Streamlit coverage explorer (sliders for band/power/heights, live
maps), drive-test replay (GIF + per-sample link-budget CSV), and a stdlib server
for the existing three.js viewer (zero dependencies).

### The honest framing, and why it matters

The demos use an **analytical model** (free space + two-ray ground reflection +
dominant-obstacle knife-edge diffraction), *not* a ray tracer. This is stated in
the README, in `ulap_demo/__init__.py`, in the app banner, and in the notebooks.

It's worth keeping that framing intact, because the interesting result depends on
it: on the pilot's rural LoS radial the model recovers Sionna's path-loss
exponent to **within 0.05** (1.78 vs 1.73) with a **0.26 dB RMS residual** after
one calibration constant — and is **completely blind** to the 361 ns delay-spread
spike the ray tracer found at 450 m. Notebook 02 is built around exactly that
contrast: where the cheap model suffices, and where you actually need the tracer.

`examples/data/newton_link_metrics.csv` is genuine Sionna RT output (14 samples)
and is what those comparisons are checked against.

## 3. The data decision (this is the part to read carefully)

`DATA.md` says the repo ships **code, not data**, and puts the Barbados Geoportal
layers under a formal Government of Barbados disclosure review — *not
redistributable* until it closes. That covers **derived products**, not just raw
shapefiles: a scene manifest of building polygons with LiDAR heights is derived
data.

The demos originally loaded exactly such a manifest. They no longer do.

**Replacement:** `examples/data/fetch_open_scene.py` builds a scene for **any
location on earth** from open sources — OpenStreetMap footprints via Overpass
(ODbL 1.0) and AWS Terrain Tiles for elevation (public domain, no API key). The
bundled sample covers the pilot area: 585 buildings, 57 m of relief, EPSG:32621.
Every layer's source, licence and heuristic is recorded in the manifest's
`provenance` block and printed by `scene.sources()`.

```bash
python examples/data/fetch_open_scene.py --lon 36.8219 --lat -1.2921 --name nairobi
```

**Scene resolution is opt-in, deliberately.** `load_scene()` takes the first of:

1. an explicit path argument,
2. `$ULAP_SCENE`,
3. the bundled open-data sample.

Pipeline output at `blender/scene_build/scene_manifest.json` is **not**
auto-detected. It used to be, and that was wrong twice over: results differed
depending on whose checkout you ran in, and anyone whose clone happened to
contain one silently ran licence-restricted data. To use the real twin:

```bash
export ULAP_SCENE=/path/to/blender/scene_build/scene_manifest.json
```

**What open data costs you** — say this out loud in any writeup:

- OSM rarely tags building **heights**. Missing ones come from a per-type default
  table; each building records its own `h_source`. The pilot had measured LiDAR.
- Terrain is ~30 m posting, not a LiDAR DTM.
- No open tower registry is bundled — `towers.template.json` is a placeholder.

## 4. Repo hygiene: what was removed and why

### `blender/` is now untracked

It's a **working directory**, not source. Everything the pipeline writes there is
both regenerable *and* geoportal-derived — the manifest, the `.ply` meshes and
the `.blend` scenes all carry the same 576 footprints and LiDAR heights as the
shapefiles. 41 files untracked (**kept on disk**, `git rm --cached`), with a
`.gitignore` rule under the public-release guard.

Still tracked under `blender/`: the pipeline notes and two `__file__`-relative
render helpers. Nothing else.

Regenerate any of it with `ulap-scope preprocess / build / export / coverage`.

### Developer paths are gone

Eight tracked files embedded `/Users/<name>/...`:

- `blender/preprocess_scene.py`, `blender/fetch_basemap.py` — hard-coded `ROOT`.
  Both were **stale pre-refactor duplicates** of `ulap-scope/ulap_scope/stages/`,
  whose copies read `$ULAP_PROJECT_ROOT`. Untracked; the packaged copies are
  authoritative. (This also collapses the duplicate findings in
  `docs/security-triage.md` from 4 to 2.)
- `docs/renders/blender_perspective.png` — Blender wrote the `.blend` path into a
  PNG `tEXt` chunk, invisible in a diff. Re-saved with metadata stripped; **pixels
  verified byte-identical**, 380 kB smaller.
- The manifest and three `.blend` files — covered by the untracking above.

### Two regression guards

In `examples/tests/`, and **both verified to fail when the bug is reintroduced**:

- `test_no_developer_paths_in_tracked_files` — reads **raw bytes** of every
  tracked file, so it catches the image-metadata case a text scan would miss.
- `test_blender_working_dir_is_not_tracked` — pins the allowed set under `blender/`.

`examples CI` now also triggers on `blender/**`, `docs/**`, `.gitignore` and
`DATA.md`, since these guards police the whole tree — a guard that doesn't run
isn't a guard.

## 6. Bugs found and fixed

Four of these were only found by testing as a newcomer would — clean virtualenvs
on a stock python.org interpreter, not the dev machine. Worth repeating that
method before any release.

| Bug | Fix |
|---|---|
| Public clones silently loaded the **geoportal scene** (the fallback found the tracked manifest), making the "open data by default" docs false | Scene resolution made opt-in |
| `fetch_open_scene.py` died with `CERTIFICATE_VERIFY_FAILED` where no CA bundle is configured — **and blamed Overpass rate-limiting** | Uses `certifi` when importable; accurate trust-store advice otherwise |
| Tower template pinned to the pilot's **metre offsets**, so any smaller `--half-width` put every site outside the box → `coverage()` failed with a bare error | Positions are now fractions of the half-width; fetcher warns; error says what to do |
| Streamlit kwarg deprecated **past its removal date**, plus a matplotlib font weight that warns on clean installs | Both dropped |
| `fresnel_nu` diverged at profile endpoints (a building *under* the receiver became an infinite wall, ν ≈ 22 000) | Distances clamped |

## 9. House rules for `examples/`

- **Commit notebooks with outputs stripped** (`jupyter nbconvert --clear-output
  --inplace`). There's a test for it.
- **Never let prose outrun the model.** If a cell prints a number, the surrounding
  markdown must agree with it. Three claims were corrected today for exactly this
  reason — including the λ² penalty, which shows up at the **5th percentile**, not
  the median, and the frequency/reach relationship, which is *not* the clean 1/f
  story once a ground reflection is in play.
- **Don't commit geoportal-derived data.** Tell-tale: EPSG:21292 and no
  `provenance` block. There's a test for that too.
- Overpass rate-limits by IP; `--osm-json` accepts an offline export from
  <https://overpass-turbo.eu>.

## 10. Publication-readiness study (added later the same day)

Seven reference paper-with-code projects were studied and turned into four
documents. Read them in this order:

| Document | What it is |
|---|---|
| [`REFERENCE_REPOSITORY_STUDY.md`](REFERENCE_REPOSITORY_STUDY.md) | What Stable-Baselines3, MMDetection, Segment Anything, Transformers, PyG, Detectron2 and Lightning actually do, with the required comparison table. Every claim cites a fetched file. |
| [`REPOSITORY_AUDIT.md`](REPOSITORY_AUDIT.md) | Our repo against the same criteria, with a four-tier gap analysis. |
| [`PUBLICATION_READINESS_CHECKLIST.md`](PUBLICATION_READINESS_CHECKLIST.md) | Paper submission → anonymous review → camera-ready → public release → maintenance. |
| [`IMPROVEMENT_PLAN.md`](IMPROVEMENT_PLAN.md) | Prioritised actions with effort, risk and acceptance criteria. |

### The finding that matters most

> **Ray-traced results are not reproducible.** Across the five Sionna RT stages
> there are **eight solver invocations and exactly one passes a seed**
> (`sionna_coverage.py:88`, `seed=41`, and only to the `PathSolver`). Every
> published figure in `docs/renders/` therefore comes from unseeded Monte Carlo
> at 10⁶–10⁷ samples per transmitter, and the run-to-run variance has **never
> been measured**.

This does not mean the numbers are wrong — at those sample counts the variance
is probably small. It means we cannot yet answer a reviewer who asks "if I run
this, do I get your figure?" Fixing it regenerates every figure, so it is
deliberately left as a decision rather than a change.

Two related findings from the same inspection:

- **Solver parameters ignore `config.py`.** `config.py:45` declares
  `samples_per_tx = 10**6`; `sionna_coverage.py:74` uses `10**7`. Cell size is
  5.0 / 8.0 / 8.0 / 8.0 / 10.0 across five stages against a declared 5.0.
  `ARCHITECTURE.md` states "config over code" — for solver settings that is
  currently not true, and editing `config.py` will not change the figures.
- **Licence inconsistency.** `ulap-scope/pyproject.toml:11` says
  `license = "MIT"`; `LICENSE`, `README.md` and `CITATION.cff` all say
  Apache-2.0.

### What was added

- [`docs/renders/README.md`](renders/README.md) — **figure provenance**. Every
  published figure mapped to its stage, command, cell size, `max_depth`,
  `samples_per_tx` and frequency, read out of the stage scripts. This is the
  MMDetection model-zoo pattern (result ↔ config ↔ artifact ↔ log) adapted to a
  project with no model zoo, and it is the highest-value artifact for a reviewer.
- **Issue templates** — bug report, *reproduction problem* (modelled on
  MMDetection's `reimplementation_questions.md`), and **new study area**, which
  is our equivalent of Transformers' `new-model-addition.yml`: an explicit
  invitation to twin somewhere new.
- **PR template** encoding `CONTRIBUTING.md`'s existing rule — describe what
  changed in the physics, not just the code.
- **`CHANGELOG.md`** in Keep-a-Changelog form, with a *Scientific behaviour*
  section so a reader can see at a glance whether a release moved a number.
- Two corrections that *remove* overclaims: `research-paper/README.md` no longer
  cites the now-untracked `blender/`, and the README states plainly that
  `study.toml` does not yet drive the pipeline.

### Where we already beat the reference projects

Worth knowing, because it is unusual: **Segment Anything shipped with four root
files and no `.github/` directory at all; Detectron2's root is two files.** Our
`DATA.md` is more rigorous than any reference project's data statement, and
`openspec/` (spec-first change control) has no equivalent in any of the seven.
The gap was never governance — it was issue templates, a changelog, and the
figure→command mapping.

### Positioning

Two genuine differentiators are currently buried in sub-READMEs:

1. **It runs on a CPU.** Every reference project assumes GPUs. This is the
   difference between a researcher without cluster access being able to use the
   pipeline or not.
2. **It works anywhere, from open data.** `fetch_open_scene.py` twins any
   coordinate on earth from OSM + open elevation, no API key, no GPU — the
   strongest adoption hook the project has.

Both read today as implementation details rather than as the invitation they
are. Changing that is a positioning decision, so it was left alone.
